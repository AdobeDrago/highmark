# Getting Started

## Access you need

- [ ] **Document Authoring access** to the `adobedrago/highmark` site. Ask the site administrator.
- [ ] **Preview and publish permission.** The site requires sign-in for preview and publish, and your account must have a role on the site. Ask the site administrator to add you.
- [ ] **AEM Sidekick** browser extension (optional). It adds Edit, Preview and Publish buttons to preview and live pages. See <https://www.aem.live/docs/sidekick>.

## How a page is put together

- A **document** in DA is one page. Its path in DA is its URL: the document `/about/our-story` is served at `/about/our-story`. A folder's `index` document is served at the folder URL with a trailing slash (`/shop/index` is `/shop/`).
- **Sections** split a page into horizontal bands. You start a new section with a horizontal rule (`---`).
- **Blocks** are tables whose first row names the block, such as `Cards Minimal Dark Withimg`. The code turns each block into its layout.
- **Section Metadata** is a small table at the end of a section. It gives the section a style, such as a coloured band.
- **Metadata** is a table at the end of the page. It sets the page's title, description, template and other options.
- **Default content** is everything that isn't in a block: headings, paragraphs, lists, links and images.

## Your first page

1. Open DA at <https://da.live/#/adobedrago/highmark/> and go to the folder the page belongs in. The URL follows the folders.
2. Find a live page of the same kind (see "Page Templates") and copy its document. This is the safest way to start, because it brings the right blocks, sections and metadata.
3. Edit the text and images. Keep one H1 per page.
4. Check the Metadata table at the bottom: `Title`, `Description` and `Template` at least.
5. Click **Preview** in DA and check the page on `aem.page`, at desktop and phone widths.
6. Click **Publish** to put it on `aem.live`.
7. If the page replaces a highmark.com URL that is still redirected, ask the development team to update `/redirects` at the same time (see "Publishing").

# Building a Page

## Sections and Section Metadata

Start a new section with a horizontal rule (`---`). To style a section, add a Section Metadata table at the end of it:

| Section Metadata | |
|:--------------------------------------------------|:--------------------------------------------------|
| Style | light-blue, center |

- `Style` takes one or more values, separated by commas. Type them in lowercase with hyphens (`light-blue`). The code normalises "Light Blue" to `light-blue` too.
- An unknown style value does nothing. Check the spelling against the tables below.
- `Regions` is a second Section Metadata row, used on shop pages and the shop header and footer. It shows the section only to visitors in the listed regions (see "Shop").

### Section styles you can use on any page

| Style | Effect |
|:------------------------|:----------------------------------------------------------------------------|
| `light` | Very light blue band (#f7fbfd), 40px padding |
| `accent` | The same light blue (#f7fbfd), 56px padding |
| `light-blue` | Light blue band (#d9ebf6), centred text |
| `blue` | Light blue band (#d9ebf6), filled buttons. With a Columns Minimal Dark block, the photo always goes left. |
| `highlight` | Blush band (#fef0ec), centred text |
| `highlight, text-band` | A centred blush callout, 780px wide |
| `dark` | Navy band (#003963) with white text and headings |
| `grey` | Grey band (#f1f4f4) |
| `center` | Narrow 760px column with centred text and buttons. Card blocks inside it are capped at 760px too; don't combine it with card grids. |

Pages on shop paths (`Theme: shop`) restyle `grey`, `center`, `dark center`, `highlight`, `blue` and `light` to match ShopX.

## Page Metadata

Add a **Metadata** table as the last thing in the document. Property names aren't case-sensitive.

| Property | Required | What it does | Example |
|:------------------|:-----------|:---------------------------------------------|:--------------------------|
| `Title` | Yes | Browser tab, share title, search results, breadcrumb label | `Learn About Medicare` |
| `Description` | Yes | Search engine snippet and this site's search results | `Find out how Medicare works...` |
| `Image` | No | Share image. It must load when the page is previewed, or the share image breaks. Leave it out to use the page's first image. | an image in the page's DA folder |
| `Template` | Usually | Page layout (see "Page Templates"). Several values are allowed, separated by commas. | `faq` or `faq, member-subpage` |
| `Breadcrumbs` | No | `true` shows the breadcrumb trail with Print and Share | `true` |
| `Breadcrumb Title` | No | Short label for this page in breadcrumb trails | `ACA` |
| `Breadcrumb Home` | No | Where the trail starts (set for `/providers` in bulk) | `/providers/` |
| `nav` | No | Header fragment (default `/nav`). Use a relative path. | `/member/fragments/bcbs/nav` |
| `footer` | No | Footer fragment (default `/footer`). Use a relative path. | `/member/fragments/bcbs/footer` |
| `Theme` | No | `shop` turns on the ZIP modal and the region links. Set in bulk for `/shop`. | `shop` |

- `Experiment`, `Campaign` and `Audience` metadata have no effect on this site.
- The bulk `/metadata` sheet already sets `nav`, `footer` and `Theme` for `/shop/**` and `/providers/**`. Don't repeat them on those pages.

### Breadcrumbs

- The trail follows the URL's folders, not the menu. Each folder in the path appears only if it is a published page.
- Each crumb's label is that page's `Breadcrumb Title`, or else its `Title` up to " | ". Changing a parent's `Breadcrumb Title` updates its children's trails once the parent is published again.
- Below 992px the trail is a single "‹ parent" back link.

## Default content conventions

### Links and buttons

A link that is alone in its paragraph becomes a button. How it looks depends on its formatting and the page template:

| Template | Plain link alone | _Italic_ link alone | **Bold** link alone |
|:----------------------|:--------------------------|:--------------------------|:--------------------------|
| Most pages | Outlined navy button | Outlined navy button | Filled blue button |
| `legal` | Plain text link | Uppercase blue text CTA | Outlined, centred button |
| `provider-content` | Plain text link | Uppercase text CTA ("Read More") | Filled blue button |
| `member-regional` | Uppercase text button | Outlined navy button | Filled button |
| `faq` | Text link | Text link | Bold text link |

- A link that shares its paragraph with other text stays an inline text link.
- **Lists of links:** put them in one paragraph with a line break (Shift+Enter) between links. Separate paragraphs would each become a button, and long labels overflow on phones.
- **Link to pages on this site with relative paths** (`/plans/medicare`). An absolute `https://www.highmark.com/...` link leaves this site even when the page exists here.
- Links to pages that haven't been migrated yet are fine. The `/redirects` sheet sends them to highmark.com or providers.highmark.com.

### Icons

Type an icon name between colons, such as `:pdf:`. These are the ones for authors:

| Icon | Use |
|:----------------------------|:------------------------------------------------------------------------|
| `:pdf:` | After a PDF link's text (legal, provider and member pages, Forms Library) |
| `:lock:` | After a provider menu item or list item that needs the Availity login |
| `:external-link:` | After a link on FAQ pages; that link then opens in a new tab |
| `:call:`, `:language:` | Shop header utility links |

### Headings, anchors and Back to Top

- Each heading gets an id from its text: "Health Savings Accounts" becomes `#health-savings-accounts`. Link to it with `#` plus the id.
- A **Back to Top** link points at `#top`.
- **Changing some headings changes the layout.** A few layouts are keyed to a heading's text: the H1s "Eating Disorders", "Mental Health Resources" and those starting "Spending Accounts", and the H2 "Elizabeth's Story". Some employer pages are keyed to their H1 too. Ask the development team before renaming these.

### Which links open in a new tab

There is no site-wide rule. These open in a new tab:

- footer links to other sites, and PDFs;
- on FAQ pages, links with the `:external-link:` icon;
- on the shop home page, links to other sites and PDFs;
- region links in the shop (see "Shop") that leave highmark.com or open a PDF;
- PDFs in provider lists.

### An image above the H1

A picture placed before the page's H1, outside any block, becomes a plain full-width hero automatically. Use Hero Minimal Dark Withimg instead; this automatic hero isn't styled for Highmark.

# Publishing

## Preview, then publish

| Environment | Domain | Purpose |
|:----------------|:----------------------------------------------------|:--------------------------------|
| Preview | `main--highmark--adobedrago.aem.page` | Check your changes |
| Live | `main--highmark--adobedrago.aem.live` | What visitors see |

**Workflow:** edit in DA, click **Preview**, check the page on `aem.page`, then click **Publish**. Saving in DA alone changes neither preview nor live.

- **Bulk:** to preview or publish many pages at once, paste their URLs into <https://da.live/apps/bulk>.
- **Fragments and sheets are published on their own.** Publishing a page doesn't publish the fragments, modal pages or sheets it uses. Publish each one you changed.
- **Sheets** are previewed and published like pages. Their URL ends in `.json`, for example `/search-suggestions.json`.
- **Search:** a page enters the site search when it is published. Its result shows its `Title` and `Description`.

## Shared documents: check before you publish

`/index` (the homepage), `/nav` and `/footer` are used by every visitor, and several people edit them. In October 2026, edits saved to them in DA but never published reverted all three to older copies, and preview showed the old homepage.

Before you publish one of them:

1. Preview it.
2. Compare the preview with live.
3. If it holds changes you didn't make, check the document's version history in DA and ask the development team before publishing.

## Redirects

The `/redirects` sheet does two jobs:

- it sends links to pages that haven't been migrated yet to the same page on highmark.com (or providers.highmark.com for `/providers/...`);
- it keeps old URLs working.

It holds about 450 rows. The development team generates it with a script.

- **Never edit `/redirects` by hand.** The next regeneration overwrites hand edits.
- **A redirect row hides a page at the same path.** If you publish a page at a URL that `/redirects` still covers, visitors keep going to the redirect's destination. A page published while it is still redirected also stays out of search and breadcrumbs. Ask the development team to regenerate and publish `/redirects` together with your page.
- **Deleting or moving a page:** ask the development team for a redirect from the old URL before you unpublish it.

# Blocks

## Inserting a block

- Open the **Library** panel in the DA editor and choose **Blocks**. Each Highmark block has an entry, and each entry lists the block's variants, each with real example content copied from a live page. Click one to insert it at the cursor, then replace the text and images.
- The Library also lists the starter blocks from the AEM Block Collection (Accordion, Carousel, Embed, Form, Hero, Quote, Tabs, Video). They aren't styled for Highmark; see "Blocks to avoid".
- You can also copy a block from a live page. Every block below names one that uses it.
- The block name in the table's first row isn't case-sensitive: `Cards Minimal Dark Withimg (narrow)` and `cards-minimal-dark-withimg (narrow)` are the same.
- **Variants** go in parentheses after the name, separated by commas: `Hero Minimal Dark Withimg (sub, navy)`.
- A block can't be placed inside another block.

## Heroes

### Hero Minimal Dark Withimg

The main page hero: a photo with the heading over it.

- **Row 1: the photo.** One image, or three images in this order: desktop, tablet, mobile. Never two. Three images switch at 768px and 428px.
- **Row 2: the text.** The H1, an optional H2 subheading, and links on their own lines. A bold link is the primary button; a plain link after it is the secondary button. Without an H1 the block becomes a shorter photo banner.
- **Alt text:** only the first (desktop) image's alt text is used. Write it there.
- **Variants:**
  - `sub` is the secondary-page hero. Add `navy` for a navy text panel on phones, or `light` for white text over the photo on desktop.
  - `intercept` is the navy glossary band (`/resources/answers`).
  - `dark` and `light` are used only on the regional member pages.

### Hero Minimal Light

A light blue band with a centred H1 and intro. One cell: the H1, then the intro paragraph(s).

## Cards

### Cards Minimal Dark Withimg

The main card grid: an image on top, a heading, text and an uppercase CTA.

- **One row per card:** an image cell first, then a cell with an H3, text and a link alone in the last paragraph. A card can have no image.
- **Images keep their own proportions; they aren't cropped.** Use 470 × 200 for two across, 370 × 200 for three across, and one ratio in each block.
- An intro in the same section is centred automatically. Don't add Style `center`; it would squeeze the cards to 760px.
- Variants `narrow`, `underline`, `mobile-center`, `compact` and `small-image` belong to particular templates. Use them only as the example pages do.

### Cards Minimal Dark Withimg 2

Two wide promo cards. The photo is a strip above the text on phones and a square beside it on desktop.

- One row per card: image | H3 (it can be a link), text and a CTA link.
- **The photo is cropped to fill its box.** Keep the subject in the centre.
- Built for two cards; more wrap in rows of two.
- A paragraph starting with a phone (`tel:`) link gets the large "Call" style.

### Cards Minimal Dark Withimg Icons

Cards with a round illustration on top.

- One row per card: image | H3, text and an optional link.
- **The image is the whole card-width canvas with the round illustration drawn on it**: 370 × 200, or 470 × 200 when the block has two cards.
- Variant `underline` adds a short blue rule under each heading. It is added automatically when the block is in a `center` section and has no links.

### Cards Minimal Dark List

Text-only cards, such as Do and Don't lists or news cards.

- One row per card, **one cell**: an H3, then a list and/or paragraphs, then a link alone in the last paragraph.
- Use H3 headings only, and only one cell per row.

### Cards Minimal Dark Iconnav

The full-width navy bar of icon-over-label quick links.

- One row per link: **icon | link**. The icon can be an image, a Google Material icon name typed as text (such as `savings`), or a `:icon:`.
- Labels show in uppercase. These links never open a new tab.
- Images show as white silhouettes, so multicolour icons become flat shapes.

### Cards (shop)

The plan cards on `/shop/`. Use the `shop` variant only on shop pages; plain Cards blocks without a template that styles them look unbranded.

## Columns

### Columns Minimal Dark

A band of text beside a photo.

- One row with the cells side by side: a text cell (H2, text, a CTA link on its own line) and an image cell holding only the image.
- **Cell order sets which side the photo is on** from 900px. On phones the photo is on top.
- A cell holding only a link to an `.mp4` file becomes a video player.
- In a section with Style `blue`, the photo is always on the left.

### Columns Minimal Dark Overlay

A full-width photo with the text laid over one side (the homepage promo bands).

- One row, two cells: text, and an image cell holding one image or three (desktop, tablet, mobile). Never two.
- Put the text cell second to put the text on the right. One block has one orientation; use separate blocks to alternate.
- **Keep the copy short.** The text lies over the photo and can run past a short image.
- Only the first image's alt text is used.
- In a section with Style `highlight`, the text sits beside the photo instead of over it.

### Columns

Plain side-by-side columns: one row per band, one cell per column. Styled for the legal pages' region cards and the leadership "request an interview" modal. Elsewhere it has a plain look.

## Accordions and tables

### Accordion Minimal Light

FAQ questions and answers.

- One row per question: **question | answer**. The question is plain text; the answer can hold paragraphs, lists and links, but no blocks.
- The first question opens automatically only on `faq`, `chip` and `answers-landing` pages.
- On FAQ pages each group is its own section: an H2, the accordion, then a `Back to Top` link to `#top`.
- **Check the preview on other templates.** Outside the `faq`, `chip`, `answers-landing`, `legal` and `provider-content` templates, the accordion is indented on wide screens to sit beside a left nav, even when there is none.

### Table

A plain data table. The first row is the header row; use `Table (no-header)` when there isn't one. It is styled on provider content pages (navy header row, ruled cells); elsewhere it looks plain.

### Table Minimal Dark Compare

Comparison and data tables (HSA and HRA, CHIP costs).

- **Row 1 holds the column labels. Make them headings,** so they show white on the coloured bar.
- The rows after it hold a label cell, then one value per column.
- A first row with text in its first cell only and no heading is removed as an import leftover. Keep at least one heading in it.
- Variant `data` gives a navy header. Bold labels in the first column turn the header bright blue and tint the label column. An empty top-left cell left-aligns the labels.
- On phones the table scrolls sideways.

## Navigation

### Cards Minimal Light Sidenav (left nav)

The left-hand section menu on About, FAQ, CHIP, legal, member and article pages.

- One row per menu item: **level | link**. The levels are:
  - `parent`, the top link;
  - `current`, this page;
  - `sibling`, a page at the same level;
  - `child`, a sub-page of the `current` or `sibling` row above it.
- Under `current`, `child` rows are an open list. Under a `sibling` they form a collapsed submenu with a chevron.
- **Use relative links.** A misspelled level shows the misspelled word as an item linking to `#`.
- Put the block first in its section, with the H1 and intro after it in the same section.
- Each page has its own copy of the menu. While the migration runs, the development team's sync tool rebuilds menus that differ from highmark.com's, so tell the team about intended menu changes.

### Provider Sidenav

The provider pages' left menu.

- One cell: a link to `/providers/fragments/sidenav/<section>`. The sections are `authorization`, `claims`, `policies-and-programs`, `provider-network`, `resources-and-education` and `communications-hub`.
- **Edit the menu once, in the fragment,** not on each page. The fragment is the section's whole tree as nested bulleted lists.
- Links in the fragment must be site paths (`/providers/...`). Add `:lock:` after an item behind the Availity login.
- The block shows the current page's parent, its children, and the current page in bold with its own children open.

### Breadcrumbs

Not a block: turn it on with `Breadcrumbs: true` in the page metadata (see "Page Metadata").

## Lists, search and panels

### Provider Panel

- **Grey box:** `Provider Panel`. Each row is one box.
- **Region box:** `Provider Panel (region)`, one row per region group: **regions | content**. The regions show as navy badges over the content, on pink. The lists use `WPA/NEPA`, `CPA/SEPA`, `DE`, `WV`, `WNY` and `NENY`.
- `Provider Panel (region, plain)` drops the pink tint.
- Inside an accordion answer, use a bold label line instead, since a block can't go inside a block.

### Provider List

The provider article and document lists.

- **Row 1:** a link to the list sheet, `/providers/lists/<list>.json`. Put no other link in the block.
- **Optional row:** `Filters | Topics, For, Date Last Updated, Document Type, Sort By`. List any of them, in the order to show.
- `Provider List (documents)` is the PDF document layout. Don't give it the `Date Last Updated` filter.
- **The sheets are generated** from providers.highmark.com by the development team. Ask them to refresh a list.

### Press Release List

The press release and event lists.

- One cell: a link to the data sheet (`/newsroom/press-releases-data.json`, `/about/events-data.json`). Put the page's H1 above the block in the same section.
- `Press Release List (events)` is the event layout.
- The sheets are generated by the development team.
- The filters are in the URL, so you can link to a filtered list.

### Search

The results page at `/search`. One cell linking `/search-index.json`. You shape the results through each page's `Title` and `Description`. A link such as `/search?q=medicare` opens a search.

### Forms Library

The regional Forms Library, with a keyword search and a category filter (`/member/bcbswny/forms`).

- **Category row:** a heading in the first cell, and an optional description in the second.
- **Form rows:** the form's name, then its link(s). Type `:pdf:` in the link text for the PDF icon, as in `:pdf: Download PDF`.
- Search covers form names only.

## Forms

### Form Minimal Light

The Contact Us, Fraud Form and News Alert forms.

- The block holds two links: the field sheet (such as `/contact-form-fields.json`), then the address the form submits to. **Don't change the submit address**; it is set by the development team.
- **The field sheet** has ten columns: `Name`, `Type`, `Label`, `Placeholder`, `Value`, `Options`, `Mandatory`, `Style`, `Id`, `Fieldset`. Every sheet needs all ten; a missing column breaks the form.
  - Types: text, email, tel, date, `text-area`, `select`, `checkbox`, `radio`, `heading`, `plaintext`, `fieldset`, `submit`, `reset`, `confirmation`.
  - `Mandatory` is `x` or `true`. `Options` for a select is a comma-separated list.
  - Style `other-of-<select name>` shows a field only while that select is set to "Other".
  - A `confirmation` row's `Value` must be a full `https://` URL.

### Zip County Form

The form in the shop ZIP modal (`/modals/zip-county`). Its rows name its sheets: `Form`, `Counties` and `Regions`.

- You can change the labels, the County placeholder and the button text in `/shop/zip-county-form`. Keep the fields named `zip` and `county`, the `submit` row and the `fieldset` row.
- The error messages are fixed in code.

### Enrollment Form

The first "Tell us about yourself" step of a shop enrollment.

- **Intro row:** one cell of copy.
- **Field rows:** label | type | options. The type is `effective-date` or `radio`; a radio's choices are comma-separated.
- **Submit row:** one link; its text is the button label.
- The answers are only checked, not sent. The button opens the link, which continues on ShopX.

### Flip Cards

The shop's life-event picker.

- One row per card: **icon | title | description | link**. The description is on the back of the card.
- The cards are a fixed size, so keep descriptions short.

## Shared content

### Fragment

Reuses shared content on many pages.

- One cell: the fragment's path, such as `/providers/fragments/service-centers`, without `.html`.
- **Publish the fragment itself** when you change it. Publishing a page doesn't publish its fragments.
- Fragment text isn't included in the page's search entry.

### Alert Banner

The homepage's "Important Notifications" strip.

- Put it at the very top of the first section.
- One cell: a heading (the title), the text, and a last paragraph holding the link.
- One per page.
- When a visitor closes it, it stays hidden for the rest of their browser session, even if you change its content.

### Modals (pop-ups)

There is no Modal block.

1. Create a document under `/modals/<name>` and publish it.
2. Link to it from any page. The link opens the document as a pop-up.

- Any link whose URL contains `/modals/` opens this way.
- If the modal page isn't published, the link does nothing.
- `/modals/zip-county` is the shop ZIP modal (see "Shop").

# Corporate Pages

## Homepage

The homepage is the DA document `/index`. Its images are in `/.index/` in DA.

- **Alert banner:** the Alert Banner block at the top (see "Blocks").
- **Hero and promo bands:** each holds three crops of its photo (desktop, tablet, mobile) in its image cell. Replace all three together.
- **Quick links:** a Cards Minimal Dark Iconnav block.
- **The footnote** ("Not all benefits...") is a section of its own.
- Compare the preview with live before publishing (see "Shared documents").

## Corporate header (`/nav`)

The header has three sections:

1. **Utility links:** a bulleted list.
2. **Brand:** the logo paragraph, then a list of icon links (each a linked icon image followed by its label).
3. **Menu:** a nested list with Style `full width`.
   - Each top-level item is a link with a sub-list.
   - Each sub-item is a dropdown column: a heading link and a list of links.
   - A list item without a link is a grey group label.

- The search box is built in automatically.
- "My Location" links to `/modals/zip-county`, so it opens the ZIP modal.

**Search suggestions:** before a visitor types, the search box lists the first five rows of the `/search-suggestions` sheet.

- Columns: `Suggestion`, plus an optional `Link`.
- A row without a link runs a search for its text.
- Edit the sheet in DA, then preview and publish `/search-suggestions.json`.

## Corporate footer (`/footer`)

1. **Brand section:** the logo, a list of linked social icons, "Customer Service" and the phone number.
2. **Link columns:** one section per column, a heading **paragraph** followed by a list of links. The layout is built for three columns. Keep each heading a paragraph, not a heading, or the column won't fold on phones.
3. **Legal text:** the last section.

- An optional section with Style `footer-top` becomes a band above the footer.
- Footer links to other sites, and PDFs, open in a new tab automatically.

## FAQ pages (`/resources/answers/faq/...`)

- **Metadata:** `Template: faq`, `Breadcrumbs: true`, and a short `Breadcrumb Title` ("ACA").
- **Sections:**
  - the left nav;
  - optionally a `right-rail` callout;
  - the H1 and intro;
  - one section per question group: an H2, an Accordion Minimal Light block, then a `Back to Top` link to `#top`;
  - optionally a `highlight` CTA band.
- **Answer paragraphs have no spacing between them.** To space two paragraphs, copy an existing spacer line from another answer; it holds an invisible character.
- To mark a link that opens a new tab, add `:external-link:` after its text.

## Health Insurance Glossary

- To add a term, add an H3 and its text under the letter's H2, in the `glossary` section.
- A new letter needs its H2 and a link to it in the A–Z list (`glossary-letters` section). A letter without terms is plain text in that list.

## Legal pages

- `Template: legal` and `Breadcrumbs: true`.
- Link conventions: a plain link alone is a text link; an _italic_ link is the uppercase text CTA; a **bold** link is the outlined button.
- Add `:pdf:` after a PDF link's text.
- Two-column content, such as the region cards, is a Columns block with two cells per row.

## Regional member pages (`/member/<region>`)

There are six regions: `bcbs`, `blueshield`, `bcbswv`, `bcbsde`, `bcbswny` and `blueshieldneny`.

- Each region page uses `Template: member-regional` and has its own `Breadcrumb Title`. Each page sets `nav` and `footer` to its region's fragments, `/member/fragments/<region>/nav` and `/member/fragments/<region>/footer`.

### Region-only sections

`Regions` works on pages with `Theme: shop` and in the shop header and footer. On other pages every region's section shows.

### Region links (tokens)

Put a token in a **link URL**, and it is filled with the visitor's region:

| Token | Filled with |
|:----------------------------------------------|:------------------------------------------------------|
| `{{zip}}`, `{{county}}`, `{{state}}` | The visitor's ZIP, county and state |
| `{{region}}`, `{{region-code}}` | The region's name and code |
| `{{brand}}` | The region's brand |
| `{{marketplace}}` | The region's Marketplace link |
| `{{brochure}}`, `{{spanish-brochure}}` | The brochure links (Spanish: Southeastern PA only) |
| `{{find-a-doctor}}`, `{{find-a-pharmacy}}` | The region's Find a Doctor and Find a Pharmacy links |
| `{{customer-service}}`, `{{about-us}}` | Customer Service (not New York), About Us (New York only) |

- **Use tokens in link URLs only.** The DA editor removes `{{...}}` from text.
- Tokens can sit inside a URL: `.../brochures/{{region-code}}_2026_ACA_Brochure.pdf`.
- **A line holding a token stays hidden until every token in it has a value.** A link whose token is empty for a region never shows there. For example, `{{customer-service}}` links don't show for New York.
- Filled links that leave highmark.com, or open a PDF, open in a new tab.
- The values come from the `/shop/regions` sheet, which the development team maintains.

### The location line

A section with Style `zip-location` shows "&lt;County&gt; County, &lt;ST&gt; &lt;ZIP&gt;" at the start of its first paragraph, ahead of the CHANGE AREA link. The paragraph is hidden until the visitor has chosen a ZIP. It is styled on the shop home page.

# Images and Media

| Method | How |
|:------------------|:----------------------------------------------------------------------------------|
| Drag and drop | Drag an image into the DA editor. It is stored next to the page, in the page's dot-folder (`/<folder>/.<page>/`). |
| Replace | Select the image in the document and drop the new file in its place |

- **Always add alt text.** In art-directed blocks (three crops), only the first image's alt text is used.
- **Art-directed photos:** Hero Minimal Dark Withimg and Columns Minimal Dark Overlay take one image or three: desktop, tablet, mobile, in that order. Never two.
- **Card image sizes:** Cards Minimal Dark Withimg images aren't cropped: 470 × 200 for two across, 370 × 200 for three across. Cards Minimal Dark Withimg 2 photos are cropped to fill, so keep the subject centred. Cards Minimal Dark Withimg Icons images are the whole 370 × 200 card canvas.
- **SVG files over 40 KB are rejected.** Convert them to PNG first.
- **Share image:** if you set `Image` in the metadata, it must load on preview, or the page's share image breaks. Leave the row out to use the page's first image.
- Images are optimised automatically when served.
- **Video:** a link to an `.mp4` alone in a Columns Minimal Dark cell plays inline. YouTube and Vimeo embeds aren't styled for this site yet; ask the development team.

# Troubleshooting

| Issue | What to check |
|:------------------------------------|:----------------------------------------------------------------|
| A published page still sends visitors to highmark.com | `/redirects` has a row for its URL, and redirects win over pages. Ask the development team to regenerate and publish `/redirects`. |
| Page not updating after publish | Wait a minute or two, then hard refresh (Ctrl+Shift+R). Check that you published, not only previewed. |
| A change to a header, footer, side nav or service-centre cards doesn't show | Fragments are published separately. Publish the fragment. |
| Block looks plain or unstyled | Check the block name and variant spelling. Check the page's `Template`: many variants and section styles only work in their template. |
| Wrong layout for the whole page | `Template` must match a template name exactly. `member-subpage` must come second (`faq, member-subpage`). |
| A link became a big button | It is alone in its paragraph. For link lists, put the links in one paragraph with line breaks. |
| A section style does nothing | Check the spelling (`light-blue`) and whether the style belongs to another template. |
| A shop link or line is missing | It holds a token with no value yet (no ZIP chosen), or no value for this region. |
| `{{tokens}}` vanished from text | DA removes them from text. Use tokens in link URLs only. |
| Every region's version shows | `Regions` only applies on pages with `Theme: shop` and in the shop header and footer. |
| A left-nav item shows a strange word and links to `#` | Its level (first cell) is misspelled. Use `parent`, `current`, `sibling` or `child`. |
| A breadcrumb is missing a parent | The parent page isn't published, or it is redirected. |
| A page doesn't show in site search | It isn't published, or it was published while a redirect covered its URL. Ask the development team to re-index it. |
| A pop-up link does nothing | The `/modals/...` page isn't published. |
| The share image shows as broken | The `Image` metadata points at a file that doesn't load. Fix it or remove the row. |
| The homepage alert doesn't come back | Visitors who closed it don't see it again in that browser session. Check in a new private window. |
| A layout changed after renaming a heading | Some layouts are keyed to heading text (see "Headings, anchors and Back to Top"). Restore the heading or ask the development team. |
